## Google Analytics

**Property ID: `548388542`** (аккаунт `tidex6`, `accounts/403380463`, ресурс
`tidex6.com`).

Это не `G-SXX19K5MZJ` — тот идентификатор для браузерного счётчика, а Data API
принимает только числовой. Путать их — потерянный час.

**Ключи сервисных аккаунтов:**

```
~/.config/google-analytics/synapse-analytics.json         чтение отчётов
~/.config/google-analytics/synapse-admin-analytics.json   управление ресурсами
```

Права `600`, каталог `700`. Живут в облачном проекте
`gen-lang-client-0154674214` (общий с Дедалом) и заведены **на весь
коллектив**: чтобы подключить другой сайт, достаточно добавить ту же почту в
его ресурс GA — новый ключ не нужен.

⚠️ В GA обоим выдана роль **Администратор**. Задумывалось разделение
«читатель / администратор», по факту оба администраторы — утечка любого из двух
даёт право менять настройки, а не только смотреть цифры.

**Как дёргать.** Токен — JWT, подписанный `private_key` из JSON, обмен на
`https://oauth2.googleapis.com/token`, scope
`https://www.googleapis.com/auth/analytics.readonly` (нужен питоновский модуль
`cryptography`). Дальше:

- отчёты — `POST analyticsdata.googleapis.com/v1beta/properties/548388542:runReport`
- список ресурсов — `GET analyticsadmin.googleapis.com/v1beta/accountSummaries`

**Серверные события (Measurement Protocol)** настроены: `ga_measurement_id` и
`ga_mp_api_secret` лежат в таблице `constants` боевой базы, ключ совпадает с
`~/work/rust/tidex6/google.api.txt`. Но события шлются **только при завершённом
вкладе в церемонию** — больше ниоткуда. Отправку платежа и отказы стоит
добавить, иначе в серверной части смотреть нечего.

## X (Twitter)

**Ключи:** `~/work/rust/tidex6/token.txt` (в `.gitignore`, в историю git не
попадал), перенесены в `~/.config/x-api/credentials.env` (`600`).

⚠️ У ключа `"Access Token OAuth 1.0 "` **пробел в конце имени** — при разборе
делать `.strip()` по ключам, иначе не найдётся.

**Два разных API, не путать:**

- `api.x.com` v2 — постинг и чтение, **OAuth 2.0** / bearer;
- `ads-api.x.com` — кампании, **только OAuth 1.0a**, OAuth2 там не работает.

Токен v2 живёт ~2 часа и обновляется задачей launchd
(`~/.config/x-api/refresh_x_token.py`) — читать его непосредственно перед
запросом, а не сохранять в переменную заранее.

**Рекламный кабинет:** `18ce55wtdf0`, статус ACCEPTED, биллинг картой, EUR.
CLI: `python3 docs/ads/x_ads_cli.py {whoami,list,funding,launch,pause-campaign}`.

### Что выяснено на своих деньгах — не повторять

**Финансовую тематику X режет.** Из трёх кампаний открутилась одна — общая, без
призыва к действию с кошельком. Обе «церемониальные», где явно про вклад,
**заблокированы как финансовая операция**. Снятие блокировки требует
сертификации рекламодателя (лицензия, юрлицо, заявка в их финотдел) — для нас
тупик.

**Та, что открутилась, привела ноль.** 29.07–05.08: 523 690 показов, 2 664
вовлечения, 527 кликов, $22.64 — и **ни одного нового контрибьютора
церемонии**. CPM $0.043, в сотню раз ниже рынка, то есть трафик мусорный.

**Подтверждено независимо через GA:** за те же 28 дней с `t.co` пришло **5
сессий**. То есть 527 «кликов» в отчёте кампании и 5 реальных визитов —
расхождение в сто раз.

⛔ **Эти 523 тысячи показов нельзя нести в заявки и презентации.** Судья
откроет ленту, увидит максимум 457 показов и один лайк на органике — и цифра
станет уликой. Разбор: `docs/ops/TRACTION_NUMBERS.md`.

**Handle'ы:** ZeroClaw — `@zeroclawlabs` (поиск по `@zeroclaw` находит чужие
пустышки, не тегать их). Наш аккаунт — `@koshak0006`. Solana — `@solana`.

## База данных

```
psql -h 127.0.0.1 -U html -d tidex6.com
```

И всё — ни ssh, ни туннелей. **Это боевая база**, не локальная копия.

Значения констант лежат в колонке **`cnt_value_json`**, не в `cnt_value_text`.
Читать: `select cnt_value_json #>> '{}' from constants where cnt_code = '…'`.
После правки константы нужен рестарт `tidex6_ws` — кэш читается при старте.

**Разграничение:** Гиперион базу только создаёт по канону forge. Схема,
миграции, сиды и константы — наша работа, ему такие задачи не ставить.

## Прод

Домены `tidex6.com`, `ceremony.tidex6.com`, `relayer.tidex6.com` — за
Cloudflare, дальше nginx, сервисы через unix-сокеты. Деплой — задачей Гипериону
(`git pull` + `cargo build --release` + рестарт юнитов).

⚠️ В `log_format` nginx **нет `CF-Connecting-IP`**, поэтому в логах видны
только адреса Cloudflare, а не реальных посетителей. Вопрос «сколько запросов с
одного адреса» без этого не решается в принципе.

⚠️ Правка `add_header` внутри `location /` **молча сносит** унаследованные
`CSP`, `X-Frame-Options`, `X-Content-Type-Options` на всех страницах. После
любой правки заголовков проверять `curl -I https://tidex6.com/`.

`location /static/` отдаётся с `Cache-Control: public, immutable` на 30 дней —
Firefox и Safari не пойдут за файлом даже по жёсткой перезагрузке.
Единственный механизм инвалидации — `?v={{ salt }}`, а `salt` меняется при
рестарте `tidex6_ws`. Поэтому то, что может понадобиться откатить срочно,
инлайнится в HTML, а не выносится в `/static/`.
